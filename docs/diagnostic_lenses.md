# 诊断视角手册

阶段 2 的"三关"是硬门槛，但真正决定诊断质量的，是**你用什么视角看这个想法**。同一个想法换个视角，可能从"不可行"变成"完全可行"。

本文档给出六类视角。每类都回答同一个问题：**这个想法在哪个维度上其实有富余量？**

---

## 视角 1：效应量 vs 噪声

### 什么时候用

用户说"我的方法涨了 X 点"。

### 怎么用

先算出三个数：

```
竞品差距 Δ_comp   = 竞品与你基线的距离
你的增益 Δ_mine   = 你说的 X
结果标准差 σ      = 该数据集的报告标准差（含 cross-validation 的话用折间差）
```

然后按这个表判断：

| 情形 | 判定 | 处理 |
|---|---|---|
| `Δ_mine < 0.5σ` | **增益不可测** | 换指标（视角 3），或增加样本/做配对检验 |
| `0.5σ ≤ Δ_mine < 2σ` | **临界** | 必须做配对检验 + 报 CI；否则诚实标注"未达统计显著" |
| `Δ_mine ≥ 2σ` | 可作主结果 | 仍要报 CI，但可支撑结论 |
| `Δ_comp > 3Δ_mine` | **方法路线不成立** | 放弃精度主张，走视角 3/4 |

**关键技巧：配对检验比增大样本更划算。**

如果两个方法在同一批样本上评测，用配对 bootstrap（按病人/病例聚类重采样 1000 次）求差值分布的 95% CI。配对能消除样本间方差，等价于"免费的样本量"。很多论文没做这一步，导致增益被低估或高估。

### 陷阱

- 标准差常常被论文**低估**（用的不是独立同分布假设下的正确形式）；
- 如果样本来自有放回重采样（同一病人多个样本），标准差会被严重低估，此时 `σ` 不可信，需按病人聚类；
- 只看均值差、不看分布重叠，是最常见的错误。

## 视角 2：既有功能的再发明

### 什么时候用

**每个想法都要先过这一关。** 用户说"我提出了一个新策略"。

### 怎么用

三步：

1. **读源码，不读论文。** 论文的默认设置、未在正文提及的参数，往往就是你"发明"的东西。
2. **列出所有与你的干预相关的可用参数**（config 文件、构造函数签名、注释里被忽略的选项）。
3. **把你的设计逐个映射到已有参数。**

判定：

| 映射结果 | 判定 |
|---|---|
| 完全等价于某个已有参数 | **这次"创新"是调参**。改写为"我们重新评估了被忽略的参数"，本身就是可发表的发现 |
| 是已有参数的**阈值化**版本（如从数量限制改为距离阈值） | **弱创新**。必须补完对照，否则归因不成立 |
| 已有参数完全无法表达 | 真新增，安全 |

### 为什么这关最容易被漏

- 用户通常先读论文再动手，而论文**不会**主动介绍"我有哪些参数可以调"；
- 论文常把默认值描述成"设计"，而不是"设置"；
- 一个实验里"设为 -1（不限）"和"设为 3"的差别，可能正好就是用户那 2 个点。

### 输出要求

诊断报告必须写出类似这样的一句：

> 该设计在实现层面等价于把已有参数 `X` 从默认值 `-1` 改为阈值化选择。**因此必做一项对照：`X ∈ {2,3,4}`。若该对照即达到同等增益，则本工作的贡献应重新表述为"对已有机制的重新评估"，这仍可发表，但定位不同。**

## 视角 3：指标错位

### 什么时候用

当方法的作用机制与评价指标不匹配时。

### 判据

问一句：**"这个方法的机理，在报告的那个指标上会被平均掉吗？"**

| 方法机理 | 平均指标会掩盖它吗 | 该换的指标 |
|---|---|---|
| 用少量信息覆盖大量数据（记忆、传播、few-shot） | **会**（少数难例被大量易例稀释） | 效率曲线：达到同精度所需的信息量 |
| 减少标注/交互成本 | 会 | 交互次数、标注时间、修正轮数 |
| 提升最坏情况可靠性 | 会 | 分位数精度、失败率、跨站点方差 |
| 加快推理 | 会 | 延迟-精度 Pareto 前沿 |
| 提升跨域泛化 | 会 | 跨站点/跨扫描仪的性能落差 |

### 标准做法：效率曲线

```
横轴：提示预算（1/2/3/5/9 个提示，或覆盖层数占比，或标注时间）
纵轴：精度

报告两个数：
  - AUC（曲线下面积）：整体效率
  - 达到目标精度所需的最小预算：可解释性最强
```

**为什么这个指标能救人**：记忆/传播类机制的本质就是"用少量真实信息扩散到全体"，在均值精度上它的贡献被稀释成 1–3 个点；但在效率曲线上，同样的机制可能表现为"所需提示数从 5 降到 3"，这是一个 40% 的相对改进。

## 视角 4：论点升格

### 什么时候用

当观察到一个**可量化的反常现象**，但说不出方法。

### 结构

一个可发表的观察型论文，需要三样东西：

1. **现象**：一个可测的、反直觉的事实（例：某编码向量的中间段余弦相似度接近 1）；
2. **机理**：解释为什么（例：该编码表只在两端有区分度，中间段训练信号不足）；
3. **后果**：这个现象导致了什么实际失败（例：因此基于"更多历史"的思路无效，必须换机制）。

这三样齐全，就是一篇**分析型论文**，不需要新方法。这类论文在领域会议有稳定位置（尤其 MICCAI / ISBI / MIDL 的分析 track）。

### 加分的第四样：可证伪的预测

> 如果机理成立，那么【某个独立实验】应该出现【某个结果】。

做了这个实验，论文从"观察"升级为"验证"。这是分析型论文与"我试了试"的分水岭。

## 视角 5：效率替代

### 什么时候用

当你的方法与某个更强的方法**精度相当但如果你更省**时。

### 常见可替代维度

| 你省的是 | 对比方式 | 常见倍数 |
|---|---|---|
| 计算量（传播次数、编码器调用次数） | FLOPs / 延迟 / 显存 | 2–10× |
| 提示预算（人工交互） | 达到同精度所需提示数 | 1.5–3× |
| 训练成本（可训练参数） | 参数量 / GPU 小时 | 10–100× |
| 数据需求 | 达到同精度所需标注卷数 | 2–10× |

### 有效性的前提

**必须在精度损失可接受的前提下省。** 如果省了 3 倍算力但精度掉 5 个点，审稿人会说"这不是同一档方法"。

标准写法：给出 **Pareto 前沿**，即"在精度 ≥ 基线 − ε 的约束下，我们省了 X 倍"。ε 取 1 个点以内通常可接受。

## 视角 6：空白定位

### 什么时候用

当检索发现"完全没人做"时。

### 危险信号

**没人做可能是两个完全相反的原因：**

- **真空白**（值得做）：有人提过需求、有人做过部分、有相关工作在侧面接近；
- **伪空白**（陷阱）：因为这条路被证明无效、或问题本身不存在、或没人需要这个能力。

### 判别方法

查三样东西：

1. **该方向有没有"负结果"论文？** 如果有论文明确说"试过，不行"，这是**伪空白**，除非你能指出它为什么不行且你能绕开。
2. **邻近领域做过吗？** 如果视频、遥感、显微、语音里都做过，只是医学影像没做，那是**域迁移**，可做但定位要诚实。
3. **有人在 discussion/future work 里提过吗？** 如果多篇论文都把这列为 future work 却没人做，**通常意味着做起来比看起来难** —— 这时要去查为什么难，难在哪一点，你能不能解决那一点。

### 判定

| 情况 | 判定 |
|---|---|
| 有需求、有部分工作、无负结果 | 真空白，可做 |
| 有明确负结果 | 伪空白，除非能说清为何能绕开 |
| 多篇列 future work 但无人做 | 通常是"难"而非"没想到"，先找难点 |
| 邻近领域已做 | 域迁移，可做，定位为验证而非创新 |

## 组合使用：一个想法的完整诊断路径

```
想法
 ├─ 视角 2（再发明）  → 是不是已有参数？
 ├─ 视角 1（效应量）  → 增益和噪声谁大？
 │   ├─ 增益够 → 走方法路线 → 视角 5（效率）加分 → 视角 6（空白）定新颖性
 │   └─ 增益不够 → 视角 3（指标）或视角 4（论点）
 └─ 视角 6（空白）    → 真空白 or 伪空白
```

**最关键的分叉点在视角 1。** 增益不够时，**不要建议用户"把方法做得更强"，要建议换指标或换论点**。这是诊断者最能创造价值的地方，也是最容易被忽略的地方——大多数人在这个分叉点会选择"再试试"，从而浪费 2–3 个月。

## 一个反面示例（供校准）

某诊断把"改动记忆编码"评为"高创新、建议尽快开展"，理由是：
- 现有工作都在改记忆库的淘汰策略，没人改编码表 → 看似空白；
- 作者的工作有理论依据 → 看似扎实。

**漏掉的三件事：**

1. 同一份源码里，另一条通路已经在用连续正弦编码 —— 所以"连续编码"不是新机制，只是换了个位置用（视角 2）；
2. 改动预期增益 1–3 点，而数据集标准差是 13 点 —— 增益不可测（视角 1）；
3. "没人改编码表"可能是因为**改了没用**，而不是没人想到（视角 6）。

**正确诊断应该是**：条件可行 —— 必须换指标（效率曲线）才能测出效应；核心价值不在方法而在"帧序号先验退化"的机理分析；建议同时做一个零代码对照来判断归因。

这就是本手册存在的意义：**同样的观察，配上正确的视角，结论会从"高创新"翻转成"需换框架"。**

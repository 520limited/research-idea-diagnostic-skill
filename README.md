# 科研选题诊断器

**在一个想法花掉你三个月之前，先花十分钟判断它值不值得做。**

一个 Claude Skill / 可复用工作流，把模糊的"这个点行不行"变成一份**可决策、可分档、可止损**的诊断报告。

> 它不负责鼓励你。它负责在投入之前发现致命伤。

---

## 谁需要它

| 你的处境 | 它帮你回答 |
|---|---|
| 有个想法，不确定够不够新 | 这个方向被别人占了多少？我还剩哪块地能站？ |
| 方法做出来了，但不确定投哪 | 你的增益和噪声谁大？这个结果能写成论文吗？ |
| 导师/合作者问"创新点在哪" | 一句话说清命题，并给出可证伪的验证路径 |
| 已经投了一个月，不确定该不该继续 | 明确的止损阈值：什么结果出现就该转向 |

**最典型的误用**：把它当成"帮我吹创新点"的工具。它的默认输出是**否定**——如果结论是"不可行"，那正是它存在的意义。

---

## 30 秒上手

```bash
pip install typst          # 唯一的可选依赖，用于导出 PDF

# 1. 检索已发表工作（带限速，不会把 arXiv 打爆）
python scripts/arxiv_probe.py --preset memory_pe --out probe.md

# 2. 按模板写诊断（或让 Agent 按 SKILL.md 的流程产出）
cp templates/report_template.md report.md

# 3. 导出：首页速览 + 补充材料
python scripts/build_report.py --md report.md --pdf report.pdf --digest \
    --meta "对象 · 日期 · 说明"
```

不装 typst 也能用——`SKILL.md` 是完整的方法论，Markdown 输出即可。

---

## 你会得到什么

一份 **11 页左右的 PDF**，但结构是「一页速览 + 九页账本」：

### 第 1 页：可以单独拿去决策

| 块 | 内容 |
|---|---|
| 结论 | 可行 / 条件可行 / 不可行 + 一句话理由 |
| 致命点 | ≤3 条，每条说清威胁与量级 |
| 可行路径 | 若需换框架，明确换成什么 |
| 分档表 | 高 / 中 / 低 / 旁路，含概率、周期、前提 |
| 止损 | 带数值阈值：出现什么结果就该转向 |
| 未核实 | 一句话交代检索限制 |

### 第 2 页起：账本

检索明细（逐篇判定终止/降级/安全）、源码或原文的关键事实、竞品数字、实验矩阵（含零代码基线与反命题组）、周期表、文献分类、风险清单。

**为什么不做成两份文件**：拆开后，人只会看首页不看依据。合在一份里，首页是结论，后面是账本。

## 凭什么信它

这套流程建立在三个反直觉的判据上。它们也是它在真实诊断中唯一有价值的部分。

### 一、效应量优先于新颖性

```
增益 < 0.5 × 标准差   →  这个增益测不出来
竞品差距 > 3 × 增益   →  方法路线不成立
```

**新颖但测不出的想法，优先级低于普通但能证明的想法。**

大多数选题讨论死于这条的反面：所有人都盯着"够不够新"，没人算"这点提升在方差面前算不算数"。

### 二、源码优先于论文

论文的默认设置与**未提及的参数**，是"重复发明"的高发区。

> **真实案例**：某工作提出"按距离筛选提示帧"作为新策略（+1.9 Dice）。而 SAM2 源码里早已有 `max_cond_frames_in_attn`，文档字符串写着 *"we only cross-attend to the **temporally closest** N conditioning frames"*。该工作通篇未提这个参数存在。
>
> 这不构成不端，但构成**归因悬空**——那 +1.9 里有多少来自"新设计"、多少来自"本来就能调"，没人区分过。

每个想法都要过一关：**你的设计，是不是某个已有参数的阈值化版本？**

### 三、指标错位是结构性问题，不是调参问题

| 方法机理 | 平均指标会掩盖它吗 | 该换的指标 |
|---|---|---|
| 用少量信息覆盖大量数据 | **会** | 效率曲线（达到同精度所需信息量） |
| 减少标注 / 交互成本 | 会 | 交互次数、标注时间 |
| 提升最坏情况可靠性 | 会 | 分位数精度、跨站点方差 |

**当一个想法"方法增量小但现象真实"时，别加大方法投入，要换框架。**

## 方法论：五阶段

完整判据见 [`SKILL.md`](SKILL.md)，六类分析视角见 [`docs/diagnostic_lenses.md`](docs/diagnostic_lenses.md)。

```
0. 拆解命题    问题 / 干预 / 指标 / 竞品 —— 四坐标填不满，说明表述不清
1. 检索新颖性  主动找"已做过"的证据，不是找支持文献
2. 三关研判    新颖性关 → 效应量关 → 审稿人必问关
3. 框架重定位  关 2 不过时，改指标或改论点，而不是加强方法
4. 分档评级    高 / 中 / 低 / 旁路 × 必做 / 应做 / 可做
5. 方案止损    实验矩阵 + 决策点排期 + 数值化止损阈值
```

**阶段 3 是整份诊断最有价值的地方**，也最容易被跳过。大多数人在效应量不足时选择"再试试"，从而浪费两个月。

### `arxiv_probe.py`

```bash
python scripts/arxiv_probe.py --preset memory_pe          # 预设词组
python scripts/arxiv_probe.py --query 'abs:"SAM 2" AND abs:"memory"' --limit 25
python scripts/arxiv_probe.py --preset cross_plane --json raw.json --out probe.md
```

内置预设：`memory_pe`、`anisotropic`、`cross_plane`、`prompt_efficiency`。查询概念至少有 3 种英文说法，只查一种必然漏。

> **实测提醒**：arXiv 对无 key 调用限制很严。本项目实测中，**4 条查询仅 1 条成功、3 条被 429 拒绝**。脚本内置了限速与退避，但只能缓解。
>
> **自动检索只能当起点，必须手动补检**：脚本跑一遍 → Google Scholar 补一遍 → 找到最接近的 2 篇后顺着引文网络再走一层。

### `build_report.py`

```bash
# 默认结构：首页速览 + 补充材料
python scripts/build_report.py --md report.md --pdf report.pdf --digest --meta "..."

# 传统长报告：封面 + 目录
python scripts/build_report.py --md report.md --pdf report.pdf --toc

# 只出中间 Typst 源，便于改样式
python scripts/build_report.py --md report.md --typ out.typ
```

分区靠 Markdown 里的一行 `---`：之前排第 1 页，之后是补充材料。

**渲染引擎是 Typst，不是浏览器内核。** 选型理由：WeasyPrint 在 Windows 缺 `libgobject-2.0-0` 直接 import 失败；Chrome headless 依赖浏览器且 `@page` 页边距框不支持；Typst 自带引擎，排版接近 LaTeX（两端对齐、首行缩进、中文断行、自动目录、页码、表格重复表头）。

配色「星辰紫 + 深蓝」，改色只改 `scripts/build_report.py` 顶部的 `PALETTE` 字典。

## 边界与诚实声明

**适用**：选题评估、创新点强度判断、可行性研判、投稿档位选择、实验方案设计。

**不适用**：论文写作润色、已定稿内容的查漏、纯文献综述撰写。

### 已知限制

1. **自动检索覆盖不全**：arXiv 限速严重，实测覆盖率约 60–70%，必须手动补检；
2. **无法评估执行能力**：只能判断"值不值得做"，无法判断"你能不能做出来"；
3. **依赖你提供的约束**：算力、时间窗、有无临床合作——这三项会显著改变档位建议，但工具拿不到；
4. **对全新范式可能失效**：流程建立在"与已有工作可比较"的前提上，对真正无先例的想法会倾向误判为"伪空白"。

**所有诊断都含未核实项，报告必须显式列出。任何声称"已完全确认"的诊断都不可信。**

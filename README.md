# 科研选题诊断器 · research-idea-diagnostic

> 把一个模糊的"这个想法行不行"，变成一份可执行、可分档、可止损的诊断报告。

这个 skill 解决的是科研中最贵的一类浪费：**在一个测不出效应的想法上投入三个月。**

它不负责鼓励，负责在投入之前发现致命伤。

---

## 为什么需要它

大多数选题讨论失败的三个原因：

1. **只找支持文献，不找反驳文献** —— 于是"没人做过"变成了一种错觉；
2. **只问方法新不新，不问指标测不测得出** —— 于是方法做对了，论文依然写不出来；
3. **没有止损条件** —— 于是"再试试"吃掉了全部预算。

本 skill 对这三件事都有强制流程。

---

## 它能输出什么

一份 12 节的诊断报告（可导出 PDF），包含：

| 章节 | 内容 |
|---|---|
| 一句话结论 | 可行 / 条件可行 / 不可行 + 核心理由 |
| 命题拆解 | 问题 / 干预 / 指标 / 竞品 四坐标 |
| 新颖性检索 | 逐篇判定「终止 / 降级 / 安全」 |
| 现状分析 | 竞品格局、SOTA 数字、差距量化 |
| 三关研判 | 新颖性关 / **效应量关** / 审稿人必问关 |
| 框架重定位 | 原命题 vs 重定位后命题 |
| 分档评级 | 高 / 中 / 低 三档 × 必做 / 应做 / 可做 |
| 实验方案矩阵 | 含零代码基线、回归组、反命题组 |
| 周期设计 | 按**决策点**组织，非任务清单 |
| 止损条件 | 带数值阈值，开工前确认 |
| 文献推荐 | 必读 / 对标 / 背景 三类 |
| 已知空白 | 未核实项与结构性风险 |

## 三条最有价值的判据

### 1. 效应量优先于新颖性

```
若 增益 < 0.5 × 标准差  →  增益不可测
若 竞品差距 > 3 × 增益  →  方法路线不成立
```

**新颖但测不出的想法，优先级低于普通但能证明的想法。**

### 2. 源码优先于论文

论文的默认设置与未提及参数，是"再发明"的高发区。

> 真实案例：某工作提出"按距离筛选提示帧"作为新策略（+1.9 Dice），而 SAM2 源码中早已存在 `max_cond_frames_in_attn` 参数，文档字符串明确写着 *"we only cross-attend to the **temporally closest** N conditioning frames"*。该项工作通篇未提该参数存在。
>
> 这不构成不端，但构成归因悬空 —— 那 +1.9 里有多少来自"新设计"、多少来自"本来就能调"，无人区分。

**每个想法都要过一关：你的设计是不是某个已有参数的阈值化版本？**

### 3. 指标错位是结构性问题，不是调参问题

| 方法机理 | 平均指标会掩盖它吗 | 该换的指标 |
|---|---|---|
| 用少量信息覆盖大量数据 | **会** | 效率曲线（达到同精度所需信息量） |
| 减少标注/交互成本 | 会 | 交互次数、标注时间 |
| 提升最坏情况可靠性 | 会 | 分位数精度、跨站点方差 |

**当一个想法"方法增量小但现象真实"时，不要建议加大方法投入，要建议换框架。**

## 快速开始

### 1. 新颖性检索（带限速，避免被 arXiv 封）

```bash
python scripts/arxiv_probe.py --preset memory_pe --out probe.md
python scripts/arxiv_probe.py --query 'abs:"SAM 2" AND abs:"memory"' --limit 25
```

> **实测提醒**：arXiv API 对无 key 调用限制很严。本项目实测中，4 条查询仅 1 条成功、3 条被 429 拒绝。脚本因此内置了串行限速（默认间隔 3s）与指数退避，但**它只能缓解、不能消除**限制。
>
> **结论：自动检索只能作为起点，必须有手动补检。** 建议流程是「脚本跑一遍 → Google Scholar 补一遍 → 找到最接近的 2 篇后顺着引文网络再走一层」。

### 2. 写诊断报告

用 `templates/report_template.md` 或参考 `examples/` 下的完整样例。

### 3. 导出 PDF

```bash
pip install typst

# Markdown → PDF
python scripts/build_report.py --md report.md --pdf report.pdf \
    --meta "作者 · 日期" --toc

# 只生成中间 Typst 源，便于手改样式
python scripts/build_report.py --md report.md --typ out.typ
```

**渲染引擎：Typst（纯 Python，无浏览器内核）**

选型过程实测了三套方案：

| 方案 | 结果 |
|---|---|
| **WeasyPrint** | ❌ Windows 缺 `libgobject-2.0-0`，`import` 即失败 |
| **Chrome headless** | ⚠️ 可用，但依赖浏览器内核；`@page` 页边距框不支持，页码要靠命令行 hack |
| **Typst** | ✅ 自带引擎，排版接近 LaTeX：两端对齐、首行缩进、中文断行、自动目录、页码、表格重复表头、避免孤行 |

中文字体按 `SimSun → Noto Serif SC → Source Han Serif SC` 回退；标题用 `Microsoft YaHei`；
**代码块的字体栈包含中文字体**，否则代码里的中文注释会掉进 `LiSu`（隶书）。

配色为「星辰紫 + 深蓝」，改色只需编辑 `scripts/build_report.py` 顶部的 `PALETTE` 字典。

## 质检清单（输出前自查）

- [ ] 是否给出了明确的"不可行"或"条件可行"判断？全篇无否定意见 = 失败
- [ ] 新颖性检索是否包含"主动寻找反驳证据"的记录？
- [ ] 是否识别出"用户以为的贡献其实是已有参数"这类情形？
- [ ] 三个档位的"必做"是否真的不同？完全相同 = 应合并
- [ ] 是否有零代码基线组？
- [ ] 止损条件是否带具体数值阈值？
- [ ] 每个结论是否标注核实状态（已核实 / 推断 / 未知）？
- [ ] 是否回答了"增益和标准差谁大"？
- [ ] 周期是否以决策点组织？
- [ ] 报告能否脱离对话独立阅读？

## 常见误诊

| 类型 | 表现 | 危害 |
|---|---|---|
| 鼓励型 | 把缺陷描述成"挑战" | 用户三个月后才发现 |
| 文献恐吓型 | 找到一篇相关论文就判死刑 | 杀死可做的想法 |
| 方法中心型 | 只评价方法新不新 | 方法对了，论文写不出 |
| 指标盲 | 接受"涨了 2 点"不问 SD | 在噪声上建论文 |
| 竞品回避 | 只和弱基线比 | 投稿被桌拒 |
| 范围膨胀 | 方法+多模态+多任务+临床一起上 | 周期翻倍，无一项做透 |

## 适用范围与边界

**适用**：选题评估、创新点强度判断、可行性研判、投稿档位选择、实验方案设计。

**不适用**：论文写作润色、已定稿内容的查漏、纯文献综述撰写。

**诚实声明**：诊断降低风险，不消除风险。所有诊断都含未核实项，报告必须显式列出（见 12 节）。任何声称"已完全确认"的诊断都是不可信的。

---

## 已知限制

1. **自动检索覆盖不全**：arXiv API 限速严重，实测覆盖率约 60–70%，必须手动补检；
2. **无法评估执行能力**：诊断只能判断"值不值得做"，无法判断"这个人能不能做出来"；
3. **依赖用户提供约束**：算力、时间窗、是否有临床合作，这三项会显著改变档位建议，但诊断者通常拿不到；
4. **对全新范式可能失效**：本流程建立在"与已有工作可比较"的前提上，对真正无先例的想法会倾向于误判为"伪空白"。

## 一页版 vs 完整版

诊断报告有两种长度，按需选用：

| | 一页速览 | 完整报告 |
|---|---|---|
| 脚本 | uild_onepager.py | uild_report.py |
| 篇幅 | **1 页** | 10–15 页 |
| 内容 | 结论 + 致命点 + 可行路径 + 分档 + 止损 | 上述全部 + 检索明细 + 实验矩阵 + 周期表 + 文献分类 + 未核实项 |
| 用途 | 快速决策、组会汇报 | 存档、开题材料、合作方沟通 |

**一页版优先。** 完整版是辅助材料——诊断的价值在于"扫一眼就能决策"，而不是篇幅。
uild_onepager.py 会在输出中报告页数，超过一页会明确提示精简。

## 文档结构：首页速览 + 补充材料

**一份 PDF，两种密度。** 这是本 skill 的默认输出结构：

| 部分 | 内容 | 排版 | 目的 |
|---|---|---|---|
| **第 1 页** | 结论 + 致命点 + 可行路径 + 分档 + 止损 | 紧凑（10pt / 0.70em） | **可独立决策**，扫一眼就够 |
| **第 2 页起** | 检索明细、源码事实、实验矩阵、文献分类、未核实项 | 常规（10.5pt / 0.82em） | 查证与执行 |

分区靠 Markdown 里的一行 `---`：

`markdown
# 标题

（这一段会排成第 1 页，必须能装下一页；装不下会自然续到第 2 页，不截断内容）

---

# 一、命题拆解

（这之后是补充材料）
`

导出：

`ash
python scripts/build_report.py --md report.md --pdf report.pdf --digest \
    --meta "对象 · 日期 · 说明"
`

`--digest` 会自动切分、切换两套版式、并在补充材料前插入分隔页。
不加 `--digest` 则输出传统的带封面与目录的完整长报告。

**为什么不是两篇文档**：诊断的价值在"一眼能决策"，但决策需要可查证。
拆成两个文件会让人只看首页不看依据；合在一份里，首页是结论，后面是账本。
